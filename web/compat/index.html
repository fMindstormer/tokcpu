How this was checked

  • The most-downloaded models on the Hugging Face Hub, taking each distinct tokenizer.json once (by its file hash). Models without one, and gated models, are left out.
  • Each tokenizer encodes 42 texts (everyday text, 15 languages and scripts, Unicode edge cases, stress cases) with special tokens added, then decodes Python's ids with special tokens skipped and clean-up off.
  • Python has two references: the tokenizers library reading the file as written, and transformers' AutoTokenizer, which adds model-specific behaviour. A difference counts only when JavaScript differs from both, or from the only one that can load the model. Where the two disagree with each other, JavaScript always sided with one of them.
  • Causes are matched from what each side produced and are best guesses. "Final sigma": lowercasing a capital Σ at the end of a word gives ς in JavaScript and σ in Python. "Whitespace": JavaScript treats U+FEFF as whitespace and U+0085 as not. "Byte fallback ignored": characters outside the vocabulary become one unknown token instead of bytes.
  • Run with python -m tokcpu compat from the tokcpu repository (daily, by a workflow, whenever a runtime has a new release), with —, on Node — (V8 —), against Python transformers — and tokenizers —, on —.
